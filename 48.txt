Patch 48 — отдельный экран курса USD + защита исторической себестоимости ручных заказов

База: актуальный main = 38542b7a2e755ac70a43afbc53dbb1d3cf834182 (`Add effective-dated USD rates`).

Цель задачи:
1. Убрать большую плашку изменения курса из шапки `/prices`, чтобы не расходовать вертикальное место.
2. Вместо неё оставить компактную кнопку перехода на отдельный экран изменения курса, по логике и визуальному принципу как `/epicentr-royalty`.
3. Одновременно закрыть найденный после Patch 47 баг: старый ручной заказ не должен пересчитывать уже сохранённую долларовую себестоимость просто при открытии, восстановлении draft или обычном сохранении без изменения даты/себестоимости.

Что должен сделать Patch 48:

A. `/prices`
- Удалить встроенную большую форму курса и историю курса из шапки.
- Рядом с кнопкой `Роялти Эпицентр` оставить одну компактную кнопку перехода на `/currency-rates`.
- Кнопка показывает текущий курс, например `Изменить курс · 45,20 ₴`.
- Кнопка занимает только высоту обычной кнопки и не увеличивает шапку по вертикали.
- Сам `/prices` по-прежнему загружает `crm_currency_rates`, потому что текущий курс нужен для отображения гривневой себестоимости и relink существующего заказа.
- Никакую логику canonical/legacy price links из Patch 44–46 не менять.

B. Новый экран `/currency-rates`
- Добавить route в `src/router/index.ts`.
- Добавить `src/pages/CurrencyRatesView.vue`.
- Визуально ориентироваться на `EpicentrRoyaltyView.vue`: отдельная страница, заголовок, кнопка `К ценам`, белые карточки на сером фоне.
- Показать текущий курс и дату, с которой он действует.
- Поля `Новый курс` и `Действует с` + кнопка `Сохранить`.
- Ниже отдельная карточка `История курса` со всеми курсами от новых к старым.
- Повторное сохранение одной даты делает upsert и исправляет курс на эту дату.
- Будущая дата разрешена; `crm_settings.usd_rate` после сохранения обновляется только курсом, действующим сегодня.
- Guest может смотреть, но не менять.
- Использовать существующую таблицу `crm_currency_rates`, новую migration НЕ создавать.

C. Исправление ручных заказов
Сейчас Patch 47 вызывает `repriceOrderDraft()` слишком широко. Исправить так:
- простое открытие существующего ручного заказа НЕ пересчитывает его `cost`;
- обычное сохранение существующего ручного заказа без изменения даты НЕ пересчитывает его `cost`;
- возврат из `/prices` после выбора одной строки цены пересчитывает только выбранную позицию, остальные долларовые позиции не трогает;
- загрузка/перезагрузка расписания курсов сама по себе не пересчитывает открытый draft;
- все долларовые позиции draft пересчитываются только когда пользователь ЯВНО меняет `Дата заказа`;
- одна позиция пересчитывается при явном редактировании её `С/С $`;
- выбранная из `/prices` долларовая позиция рассчитывается по курсу даты draft;
- уже существующая ненулевая историческая себестоимость marketplace-заказов и ручных заказов от простого sync/open/save не меняется.

Пример обязательной проверки:
- старый ручной заказ: дата 09.09.2026, `costUsd=10`, сохранённый `cost=452`;
- в истории курса позже появилась/исправлена запись, которая теоретически могла бы дать другой гривневый результат;
- открыть заказ и нажать `Сохранить изменения`, не меняя дату и С/С → должно остаться ровно 452;
- затем пользователь вручную меняет дату заказа на 10.09.2026 → все USD-позиции этого draft пересчитываются по курсу 10.09;
- пользователь меняет только `С/С $` одной позиции → пересчитывается только она;
- пользователь выбирает из `/prices` новую строку только для одной позиции → остальные позиции не меняются.
