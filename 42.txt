Patch 42 — привязка себестоимости без зависимости от размера для Prom и Эпицентра

База для подготовки: актуальный main на момент создания Patch 42 = 3970928766539b7ca1c96e49f63bdfa246a3b2ec.

Цель:
1. Одна ручная привязка товара к строке «Цен» должна работать для всех размеров того же товара на Prom и Эпицентре.
2. Размер остаётся частью позиции заказа для отображения и сопоставления конкретной вариации, но не должен создавать отдельную привязку себестоимости.
3. Существующие привязки и ручные значения себестоимости нельзя потерять или массово перепривязать.

Почему исправление нужно:
- Сейчас crm_product_price_links хранит точный marketplace_product_key.
- У разных размерных вариаций площадка может вернуть разные ключи: например offerId на Эпицентре или SKU/external_id на Prom.
- Поэтому точный lookup не всегда находит уже созданную привязку другого размера.
- Повторная точечная синхронизация сама по себе это не исправляет, если ключи вариантов различаются.

Требуемая логика Patch 42:
1. Сохранить точный marketplace_product_key как основной и наиболее безопасный способ поиска.
2. Для Prom и Эпицентра добавить второй, size-independent lookup по «семейству товара».
3. Семейные алиасы формировать только когда размер известен:
   - размер берётся из уже вычисленного size позиции;
   - для старых link-строк, где size исторически NULL, разрешается безопасно вывести размер из product_title по тем же типовым форматам: маркированный «розмір/размер/size/р.» либо отдельный размер в конце названия перед необязательным блоком в скобках;
   - 3-значные числа не считать автоматически размером, чтобы не превращать номер модели вроде 720 в размер.
4. Для семейства использовать два независимых алиаса:
   - кодовый: только когда точный merchant-код заканчивается на реально определённый размер через разделитель. Для Prom это sku:/external:, для Эпицентра offer:. Пример: offer:717-720-L и offer:717-720-XL -> один family code 717-720;
   - текстовый: нормализованное название товара, из которого удаляется только реально определённый размер, включая размерный суффикс внутри финального артикула в скобках. Пример: «Reis Foreco-TS L (717-720-L)» и «Reis Foreco-TS XL (717-720-XL)» -> один family title.
5. Не использовать общий family lookup для Kasta. Её существующую логику не менять.
6. Защита от ложной склейки обязательна:
   - точные link-ключи имеют приоритет;
   - семейный алиас активен только если все существующие link-строки, породившие этот алиас, указывают на один и тот же price_item_id;
   - если под одним family alias обнаружены разные price_item_id, этот алиас считать неоднозначным и НЕ использовать автоматически.
7. Когда синхронизация второго размера нашла себестоимость через семейный алиас:
   - применить тот же price_item_id к позиции;
   - если себестоимость позиции допускает существующий autofill, подтянуть стоимость по прежним правилам resolvedOrderItemCost();
   - создать/«продвинуть» точную crm_product_price_links запись для фактического marketplace_product_key этого размера, чтобы следующий lookup был прямым;
   - при создании такой точной записи сохранить product_title и фактический size.
8. Существующий legacy-переход со старого точного marketplace_product_key на новый точный ключ сохранить; при promotion также сохранять size.
9. При ручной привязке в PricesView больше не писать size=NULL: сохранить linkSize как метаданные. Это НЕ означает привязку по размеру — size нужен только для безопасного построения семейного алиаса.
10. В HomeView считать позицию привязанной, если у неё уже есть priceItemId, даже если локальный список crm_product_price_links ещё не успел перечитаться после семейного fallback/promotion.
11. Не менять resolvedOrderItemCost() семантически:
   - ручная себестоимость остаётся приоритетной;
   - Patch 42 не должен молча перезаписывать уже существующую ненулевую себестоимость;
   - задача — привязать price_item_id и использовать существующие правила autofill.
12. Новую миграцию БД не создавать: текущие поля crm_product_price_links (marketplace_product_key, price_item_id, product_title, size) достаточны.

Файлы Patch 42:
- supabase/functions/_shared/price-link-family.ts — новый чистый helper построения size-independent family aliases.
- supabase/functions/_shared/price-cost.ts — загрузка точных + однозначных семейных snapshot, lookup и сохранение size при promotion.
- supabase/functions/sync-prom-orders/index.ts — family fallback для Prom + promotion точного ключа варианта.
- supabase/functions/sync-epicentr-orders/index.ts — family fallback для Эпицентра + promotion точного ключа варианта.
- src/pages/PricesView.vue — сохранять linkSize в crm_product_price_links.size.
- src/pages/HomeView.vue — priceItemId также означает, что позиция привязана.
