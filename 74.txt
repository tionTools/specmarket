WHY THIS PATCH EXISTS
1. crm_order_items replacement is currently DELETE then INSERT in four paths. If INSERT fails after DELETE, the order can lose all item rows. Patch 74 moves the replacement into one PostgreSQL RPC transaction.
2. Prom seller-paid delivery fallback is incomplete. Confirmed production cases:
   - Rozetka Delivery can be displayed as "Магазины Rozetka" while delivery_provider_data.provider is absent; seller tariff must still resolve to 10/30 UAH.
   - Prom Nova Poshta promotion "Дешева доставка" has confirmed cabinet conditions: cart minimum 200 UAH, seller pays 10 UAH from 200 UAH and 30 UAH from 700 UAH; Prom pays the remainder. The existing Prom API boolean has_order_promo_free_delivery is already read by sync-prom-orders and is passed to the resolver only for this guarded fallback.

SCOPE
Patch 74 intentionally contains only:
1. Atomic crm_order_items replacement through service-role-only RPC replace_crm_order_items().
2. Prom / Rozetka Delivery fallback: if delivery_provider_data.provider is absent, use the already-resolved carrier/delivery_option; labels containing Rozetka use the existing 10/30 tariff.
3. Prom / Nova Poshta promo fallback: only when has_order_promo_free_delivery=true AND carrier/provider resolves to Nova Poshta; 0 below 200 UAH, 10 from 200 through 699.99, 30 from 700 upward.
4. Regression tests for precedence and tariff boundaries.

PRECEDENCE THAT MUST NOT CHANGE
manual shipping > explicit seller delivery cost from Prom API > marketplace tariff fallback > 0.
Manual values must never be overwritten by either fallback.

OUT OF SCOPE
- All authorization/RLS/realtime/RPC hardening. That will be a separate Patch 75 after production RPC/realtime review.
- Manual-order date handling.
- Reconciliation/TTN accounting; current business rule is intentional.
- Android pagination, tracking batching, PricesView persistence, Vue versions, CI/CD, HomeView decomposition, Kasta royalty fallback, Epicentr batching, dark mode, deployment layout, or Patch53/local artifacts.
