Goal
Исправить зелёный блок «Получены перевозчиком — подтвердить в Prom», сохранив существующий workflow с чекбоксами.

Required behavior
1. ОСТАВИТЬ существующие чекбоксы у заказов и «Выбрать все».
2. Переместить существующую массовую кнопку «Подтвердить в Prom (N)» из правой стороны ВЛЕВО внизу зелёного блока.
3. Рядом добавить вторую массовую кнопку «Не подтверждать (N)».
4. Обе кнопки работают с ОДНИМИ И ТЕМИ ЖЕ отмеченными чекбоксами заказами.
5. «Подтвердить в Prom» сохраняет текущее поведение: выбранные заказы Prom переводятся в «Виконано».
6. «Не подтверждать» НЕ ДОЛЖНА ничего менять в Prom. Она только навсегда убирает выбранные заказы из этой зелёной плашки CRM.
7. Это исключение должно храниться в общей БД, не в localStorage, чтобы refresh/realtime/другое устройство не возвращали заказ.
8. Полностью принятый возврат автоматически исключается из зелёной плашки.
9. Частично принятый возврат сам по себе НЕ исключается.
10. Если позже статус Prom вручную изменён на выполненный/отменённый/возвратный и CRM синхронизирована, существующая логика также должна убрать заказ из зелёной плашки.
11. Нужен серверный guard: заказ, уже вручную исключённый из этой плашки или полностью возвращённый, нельзя провести через существующий completeExternalIds даже из старой вкладки браузера.

Data model
Добавить nullable column:
- public.crm_orders.prom_completion_dismissed_at timestamptz

Этот флаг означает только:
«Больше не предлагать этот заказ CRM для подтверждения Prom».
Это НЕ отмена заказа, НЕ статус возврата и НЕ влияет на финансы/учёт.

Implementation notes
- computed зелёной плашки исключает:
  a) promCompletionDismissedAt;
  b) полный принятый возврат через существующий isOrderFullyReturned(order);
  c) существующие выполненные/отменённые/возвратные статусы Prom.
- «Не подтверждать» вызывает sync-prom-orders с dismissCompletionExternalIds.
- Этот action только пишет prom_completion_dismissed_at и возвращает changedOrderIds, чтобы существующий refresh/realtime обновил UI.
- completeExternalIds дополнительно отклоняет dismissed и fully-returned заказы на сервере.
- Пока выполняется одна массовая операция, обе кнопки disabled.

- 0 выбранных => обе массовые кнопки disabled;

- «Не подтверждать» => запрос на изменение статуса Prom НЕ отправляется; выбранные строки исчезают из зелёной плашки после refresh CRM;
