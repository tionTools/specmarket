Confirmed current-code defects:
- Android 'Позвонить', Viber and Telegram all use recipientPhone(), not buyer phone. Buyer was hidden in Extras.
- recipientPhone() falls back to order.phone, including Prom where it is now confirmed that order.phone is the buyer in CRM and delivery.recipientPhone is the recipient. No recipient-to-buyer cross-call.
- Offline header reflects only Realtime subscription status, even if REST refresh works.
- watch() waits forever after successful subscribe even if channel later loses subscription; cleanup can also wait without bound.
- refresh() lacks a deadline and refuses retries if loading is still true. These are concrete stuck-state risks. No production network trace establishes one exclusive root cause.

Patch behavior:
1. Buyer (crm_orders.phone) is the primary, explicitly labelled contact in Android details. Dialer, Viber and Telegram all use BUYER only. Recipient name and number stay visible in their own section, without a mistaken fallback for Prom. If buyer number is missing, do not substitute receiver.
2. Restore network subscription with validated default-network callbacks (ACCESS_NETWORK_STATE); retry on foreground and from manual refresh (top-bar icon / pull-to-refresh). A forced retry cancels an old refresh and restarts Realtime; generations block stale callbacks.
3. Bound order refresh to 30s, Realtime subscribe to 25s, old watcher join to 7s, channel removal to 5s. Retry Realtime if a subscribed channel disconnects. Cache remains available while offline. Display 'CRM доступна · live-подключение восстанавливается' when REST succeeded but Realtime has not.
4. Add model/status unit tests. Existing push, auth, acceptance and marketplace actions must remain unchanged.
