Patch 80 — корректный разбор времени события Nova Poshta

База main: d0719731530c778a4dff74461bfdf4434702cb19

Причина:
Patch 79 правильно переключил UI на delivery.trackingEventAt, но formatter не учитывает реальный формат Nova Poshta DateScan: `HH:MM DD.MM.YYYY` (например `12:11 14.09.2026` и `15:52 12.09.2026`).

Из-за fallback `new Date(source)` получаются два дефекта:
- день > 12: строка становится Invalid Date, поэтому время вообще не показывается;
- день <= 12: V8 может интерпретировать `DD.MM` как `MM.DD`, поэтому `15:52 12.09.2026` превращается в `15:52 09.12.2026`.

Scope:
- src/pages/HomeView.vue

Что меняет Patch 80:
- до остальных локальных форматов явно распознаёт Nova Poshta time-first: `HH:MM DD.MM.YYYY` и `HH:MM DD-MM-YYYY`, с необязательными секундами;
- валидирует компоненты даты через существующий isValidDeliveryStatusLocalDate;
- для неизвестных строк без явного timezone больше НЕ вызывает `new Date(source)`, чтобы браузер не угадывал локальный формат;
- ISO с Z/offset по-прежнему разбирается через Date и переводится в Europe/Kyiv;
- layout, центрирование timestamp, trackingEventAt и render-оптимизация Patch 79 не меняются;
- backend/Supabase не менять: trackingEventAt уже содержит нужное carrier-время.

Обязательные проверки formatter после применения:
- `12:11 14.09.2026` -> `12:11 14.09.2026`
- `15:52 12.09.2026` -> `15:52 12.09.2026` (НЕ `09.12.2026`)
- `12:36 07.04.2023` -> `12:36 07.04.2023`
- `14.09.2026 18:52:03` -> `18:52 14.09.2026`
- `2026-09-14 12:11:00` -> `12:11 14.09.2026`
- `2026-09-14T15:52:00Z` -> `18:52 14.09.2026` (Europe/Kyiv)
- invalid -> пустая строка
