Goal
Store the "copied for Excel" mark for each CRM order in Supabase and show a "Не в Excel" historical filter with count. Existing localStorage flags should be migrated once from the browser where they were recorded; records not flagged in localStorage must NOT be auto-marked as copied. Allow manual mark/unmark when the user checks existing Google Sheets.

Exact scope:
1) src/pages/HomeView.vue
2) src/features/orders/types.ts
3) supabase/migrations/20260923130000_crm_order_excel_copied.sql

Database design
- One boolean crm_orders.excel_copied NOT NULL DEFAULT false. Existing rows without a mark become false. No new table/index or historical blanket update.
- Narrow, authenticated-only SQL RPC set_crm_orders_excel_copied(uuid[], boolean), disallow guest and anonymous calls. It updates ONLY the mark and returns the matched row count. Maximum 100 IDs per call. Do not grant general update rights to unrelated columns.
- Existing marketplace/order saves have explicit field lists and must not reset excel_copied.

Frontend behavior
- Use DB excel_copied as the source of truth, not localStorage. Click Excel: copy the tab-separated row, then persist true; on failure do not falsely change the mark. Button remains gray after page reload and on another device.
- Manual "Уже в Excel" / "Снять отметку Excel" handles pre-existing rows or mistakes; no clipboard operation for manual toggle.
- "Не в Excel · N" shows non-marked normal-list orders independent of selected date; exclude cancelled-before-shipment and fully returned lifecycle states in line with main-list behavior; preserve search and platform narrowing after entering the filter. Leave the registry draft alone (filter disabled in registry mode).
- One-time import of old localStorage key specmarket-crm-copied-excel-orders: only IDs mapped unambiguously to CRM remote UUIDs and currently false. Batches of 100; set marker specmarket-crm-copied-excel-migrated-v1 ONLY after all writes succeeded; failed imports can retry; skip ambiguous duplicate display IDs for manual review. Do not clear or overwrite the legacy localStorage list.
- A clipboard copy is NOT proof that the row was pasted into Excel/Google Sheets. The boolean tracks the CRM mark, not actual presence in Sheets.

Existing orders: IMPORTANT
- Old true marks recorded in THIS browser will be imported once after the migration is deployed and the new UI is loaded.
- All other historical orders default false, even if the user previously pasted them in Sheets without clicking the CRM Excel button. Do not mark them all copied. Ask user to compare with their actual Google Sheet and manually mark confirmed existing rows using "Уже в Excel".
- If localStorage was in a different browser, its flags are not visible until that browser runs the migration; avoid concurrent manual unmarks on the other device before it has run. No Google Sheets connector or automatic matching is added in this patch.
