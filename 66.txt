- Пользователь выбирает PDF.
- Edge Function send-order-label-email:
  - проверяет авторизацию;
  - guest@gmail.com запрещён;
  - повторно читает заказ из crm_orders;
  - не доверяет carrier/TTN/email-body из браузера;
  - принимает только PDF до 5 МБ и максимум 5 страниц;
  - извлекает текст PDF через unpdf 1.8.1;
  - Rozetka: извлекает самостоятельный PRM-...;
  - Meest: извлекает самостоятельный NNN-NNNNNNN и НЕ принимает длинный технический штрихкод вроде 723-1356399001001HSU;
  - сравнивает PDF ТТН с текущей ТТН заказа;
  - mismatch => НЕ отправляет и возвращает:
      Бирка не соответствует заказу.
      ТТН заказа: ...
      В бирке: ...
  - если ТТН не извлечена => НЕ отправляет;
  - перед фактической отправкой ещё раз перепроверяет carrier/TTN заказа;
  - body и subject письма:
      Розетка PRM-...
      Мист NNN-NNNNNNN
  - прикладывает выбранный PDF;
  - recipient берёт из user_metadata.labelRecipientEmail, fallback prozaxist.ocean@gmail.com;
  - отправляет через Resend;
  - при успехе сохраняет в delivery:
      labelEmailSentAt
      labelEmailSentTtn
      labelEmailMessageId
  - отметка сохраняется только после успешного Resend;
  - сохранение отметки защищено от параллельного изменения заказа через updated_at, чтобы не перезаписать свежий delivery;
  - если письмо уже отправилось, но отметка безопасно не сохранилась, функция явно сообщает emailSent=true и предупреждает не отправлять повторно до проверки почты.
- В карточке после успеха показывать «Бирка отправлена» + дата/время.
- Для текущей ТТН повторная отправка допускается только после confirm.
- Если ТТН позже изменилась, старая отметка не считается отправкой новой ТТН.
- sync-prom-orders, sync-epicentr-orders, sync-kasta-orders обязаны сохранять labelEmail* поля при следующих marketplace sync.
- sync-delivery-tracking уже merge-ит delivery и не требует изменения.
- Никаких DB migrations в этом Patch.
