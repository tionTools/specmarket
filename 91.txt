What changes:
- Adds Firebase Cloud Messaging to Android using google-services.json for ua.orders.crm.
- Registers a stable per-install device id and the current FCM token after Supabase authentication.
- Notification permission and the existing "new order notifications" setting also control server push registration.
- Logout removes the device registration before signing out when possible and disables local push display immediately.
- Adds FirebaseMessagingService for data messages so Android can build the same local notification and preserve the exact-order PendingIntent from Patch 89.
- FCM and Realtime use the same order-id notification identity plus a persistent 7-day order-id dedupe guard, so one order does not generate two alerts when both channels deliver it.
- Keeps existing crm:orders / order_changed Realtime behavior unchanged.
- Adds crm_push_devices for device tokens. Direct public/anon/authenticated table access is revoked; Edge Functions use service-role access.
- Adds manage-push-device, which manually validates the current Supabase user and rejects guest@gmail.com.
- Adds send-order-push, authenticated internally by the existing crm_sync_cron_secret, which obtains a Firebase HTTP v1 OAuth token from the configured Firebase service account and sends a high-priority data push.
- Adds AFTER INSERT trigger on crm_orders. The trigger queues send-order-push through pg_net. It only acts on inserts; status updates do not create a new-order push.
- send-order-push only notifies for Prom/Epicentr/Kasta new-order candidates without TTN/cancel/return signals and removes unregistered FCM tokens.
