PATCH 55 — исправить оборот при возвратах

Источник истины: текущий main. На момент подготовки патча main = 17c231b24c4ad0f7dc7a01368be9c490be90a595.

Цель:
- физически отправленный заказ с сигналом отмены/возврата остаётся в отчётном наборе;
- до принятия возврата оборот учитывает всю оставшуюся сумму;
- при частичном принятом возврате оборот учитывает только remaining quantity;
- после полного `Принять возврат` заказ остаётся доступен для расчёта фактического финансового результата, но его оборот равен 0 через `getNetOrderAmount`;
- отмена до физической отправки не входит в отчёт;
- правило едино для Prom / Epicentr / Kasta / Р/С / Сайт.

Контрольный кейс S5TSAE5:
- 05.09.2026, Kasta, 1 × 676 грн, printedAt есть, статус `Скасовано / Відмова від отримання`;
- до `Принять возврат`: lifecycle = return_pending, turnover = 676;
- после полного принятия 1/1: lifecycle = return_completed, turnover = 0;
- pre-shipment cancellation с одной только ТТН в отчёт не попадает.
