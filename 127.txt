Context
Patch 125 forward running-balance logic is deployed.
Patch 126 only changed the CURRENT calendar day's opening fallback. At the time of the Patch 126 smoke test the local date was already 20.09.2026, so Patch 126 could not change the historical 19.09 calculation.

Observed after Patch 126:
- 18.09.2026 +1248.72 -> 7248.21
- 19.09.2026 +125.37 -> null
- 19.09.2026 +626.85 -> null
- overall account balance -> 8000.43

Concrete defect in current helper
novapay-data sends ALL conducted documents from GetPaymentsList into extractAccountMovement().
Documents not involving the selected account IBAN get:
  direction: 'unknown'

assignRunningBalances() currently treats any unknown-direction document as an INVALID DAY:
  invalidDates.add(date)

Therefore one unrelated conducted NovaPay document on 19.09 is sufficient to discard both otherwise-calculable 19.09 balances.

That behavior is wrong.
A document that is neither a debit nor a credit for the selected account must not invalidate that account's day.

Patch 127 is intentionally tiny:
- direction unknown => ignore that document;
- known credit/debit with invalid amount or timestamp => still invalidates the day;
- all known account movements still participate in + / - running balance;
- final calculated close must still equal authoritative closing balance;
- no fallback math is added.

Expected production math remains:
18.09 close = 7248.21
19.09 opening = 7248.21
13:56:25 +125.37 = 7373.58
19:47:04 +626.85 = 8000.43
