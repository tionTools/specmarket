Что должен сделать Patch 67
- При запуске сразу показывать сохранённые заказы из локального кеша текущего CRM-аккаунта.
- Временный пустой ответ сервера не должен очищать уже известный список.
- После создания baseline не перезагружать всю CRM при каждом входе: забирать изменения по updated_at и merge по order.id.
- Realtime продолжает обновлять/добавлять заказы; после reconnect/возврата в foreground выполняется контрольный sync пропущенных изменений.
- Новые ранее неизвестные заказы определять одним правилом с визуальной плашкой НОВЫЙ ЗАКАЗ.
- Первый baseline/первая установка не должны массово озвучивать старые заказы.
- Новый заказ, пойманный Realtime или найденный контрольным sync, должен дать одно уведомление; повторно один и тот же order.id не озвучивать.
- На Android 13+ при включённых уведомлениях корректно запросить POST_NOTIFICATIONS; ожидающее уведомление не терять до выдачи разрешения.
- Ограничение сохранить честным: если Android полностью убил процесс, без server push/FCM гарантированного фонового уведомления нет.
- В карточке клиента оставить Позвонить и добавить Viber/Telegram по нормализованному международному номеру с безопасным fallback, если приложение не открылось.
- В списке и деталях вместо текста Пром/Эпицентр/Каста показывать маленькие реальные логотипы из Web CRM assets; Р/С и Сайт оставить текстом.
- Существующую marketplace acceptance/business logic не менять.

Контрольные случаи
- Кеш уже есть + сервер временно вернул [] => список заказов не исчезает.
- Кеш есть + появился новый order.id => новый заказ добавляется без полной перезагрузки старых.
- Изменился существующий order.id => запись обновляется, дубликат не создаётся.
- Realtime INSERT пропущен, но заказ найден sync после reconnect => заказ появляется и уведомляется один раз.
- Первый baseline на устройстве => старые заказы не дают шквал уведомлений.
- Prom/Epicentr/Kasta без ТТН и не cancelled/returned => визуальный НОВЫЙ ЗАКАЗ и то же правило для уведомления.
- Разрешение POST_NOTIFICATIONS отсутствует => запросить его; после разрешения ожидающее уведомление может быть доставлено, без повторов.
- Viber/Telegram получают номер в международном формате +380...; отсутствие приложения не приводит к падению.
- Prom/Epicentr/Kasta => логотипы; Р/С/Сайт => текст.
