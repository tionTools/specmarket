4. Постоянная подпись Android APK
Цель: начиная с Android 0.5 все APK должны подписываться одним и тем же постоянным release-ключом. Ключ и пароли нельзя коммитить в репозиторий.

Ожидаемые GitHub Secrets:
- `ORDERS_RELEASE_STORE_B64`
- `ORDERS_RELEASE_STORE_PASS`
- `ORDERS_RELEASE_ALIAS`
- `ORDERS_RELEASE_KEY_PASS`

Сначала выполни:
`gh secret list --repo tionTools/specmarket`

Правила:
- Если все 4 секрета уже существуют — НЕ создавай новый ключ и НЕ перезаписывай секреты. Используй существующую постоянную подпись.
- Если ни одного из 4 секретов нет — создай один постоянный keystore локально ВНЕ репозитория и один раз запиши его в GitHub Secrets.
- Если существует только часть из 4 секретов — остановись и сообщи о неполной конфигурации. Не перезаписывай существующие секреты и не генерируй новый ключ.
- Если `gh` не позволяет читать/записывать Secrets — остановись до commit/push и сообщи об этом. Не пушь workflow, который гарантированно упадёт без секретов.

Если все секреты отсутствуют, создай ключ так:

```powershell
$repoRoot = (Get-Location).Path
$signingDir = Join-Path (Split-Path -Parent $repoRoot) 'android-signing'
New-Item -ItemType Directory -Force -Path $signingDir | Out-Null
$keystore = Join-Path $signingDir 'orders-release.jks'
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$pass = [Convert]::ToBase64String($bytes)
$alias = 'orders'
keytool -genkeypair -v -keystore $keystore -alias $alias -keyalg RSA -keysize 4096 -validity 10000 -storepass $pass -keypass $pass -dname 'CN=Orders Android,O=SpecMarket,C=UA'
@("alias=$alias","password=$pass") | Set-Content -Encoding UTF8 (Join-Path $signingDir 'orders-release-credentials.txt')
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes($keystore))
gh secret set ORDERS_RELEASE_STORE_B64 --repo tionTools/specmarket --body $b64
gh secret set ORDERS_RELEASE_STORE_PASS --repo tionTools/specmarket --body $pass
gh secret set ORDERS_RELEASE_ALIAS --repo tionTools/specmarket --body $alias
gh secret set ORDERS_RELEASE_KEY_PASS --repo tionTools/specmarket --body $pass
```

Keystore и `orders-release-credentials.txt` должны остаться вне репозитория. Никогда не показывай значения секретов в отчёте и не добавляй их в Git.

Обязательно проверь:
- `applicationId` остаётся `ua.orders.crm`.
- Android версия стала `versionCode = 5`, `versionName = "0.5"`.
- Prom / Эпицентр / Kasta без ТТН и без отмены/возврата визуально имеют лиловую плашку `НОВЫЙ ЗАКАЗ`.
- При появлении ТТН лиловая плашка исчезает и дальше показывается обычная CRM-логика цветов/статусов.
- Р/С и Сайт не считаются визуально новыми по этому правилу.
- Логика marketplace acceptance не расширена: Kasta acceptance остаётся недоступной; Prom и Epicentr работают по существующим правилам.
- Уведомления о новых заказах не подменены новой визуальной TTN-логикой.
- В деталях заказа при непустом номере клиента есть удобная кнопка звонка. Она открывает штатный Android dialer через `ACTION_DIAL` с уже подставленным номером; прямой автозвонок и разрешение `CALL_PHONE` не нужны.
- Существующие доставка, детализация, принятие заказов и сохранение списка после detail refresh не сломаны.

9. Важный переход со старой версии
Старые Android 0.3/0.4 были собраны с разными одноразовыми debug-ключами. Поэтому переход на первый APK 0.5 с постоянным release-ключом требует один последний чистый переход: удалить старую установленную версию, установить 0.5 и один раз войти в аккаунт. Это неизбежно без старого приватного debug-ключа.

После этого все будущие версии должны сохранять `applicationId = ua.orders.crm`, увеличивать `versionCode` и подписываться тем же постоянным release-ключом. Тогда они будут устанавливаться поверх приложения и сохранять данные/сессию.
