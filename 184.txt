BUSINESS RULES
- On first arrival of an order previously unknown in CRM's tracked order IDs (any platform), show top new-order toast and sound once, irrespective of TTN, status, payment, or processing on the marketplace.
- Existing orders updated later must never trigger a new-order alert.
- Preserve the initial-load baseline: do not produce bulk notifications for the existing database on first startup. Do not replay alerts on refresh/reload for already-known orders.
- Preserve the existing enable/disable switch for notifications.
- Purple «НОВЫЙ ЗАКАЗ» badge is SEPARATE and must remain unchanged: show only when no TTN and not cancelled/returned, for all five platforms.
- Manual order creation performed locally in the CRM is not a newly *synced* order; this patch changes only notifications from incoming CRM reads. Do not alter manual order save flows.

ROOT CAUSE (CONFIRMED IN MAIN)
- Realtime INSERT fills pendingNewOrderIds. notifyNewOrder() runs only if this pending ID was present when a row was inserted into local orders.
- Normal reconciliation, manual sync, tab-focus refresh and recovery can add rows with no preceding INSERT event, producing no toast/sound.

EXACT PATCH
- Remove obsolete pendingNewOrderIds set and INSERT recording.
- In refreshRemoteOrders(), on index === -1, after the newly fetched order is added to orders.value, notify only when hasRemoteOrderBaseline && !knownRemoteOrderIds.has(order.remoteId).
- registerRefreshedRemoteOrders() subsequently adds this ID to knownRemoteOrderIds, so subsequent refreshes of the same order are silent.
- Do not touch badge, notification message, sound, readback safety, orders RLS, Supabase tables, Edge functions, or any synchronizations.
