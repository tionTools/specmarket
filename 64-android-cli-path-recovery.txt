2. Не полагайся на WinGet PATH. Установи Android CLI официальным локальным Windows installer через `cmd.exe`
Google официально поддерживает локальную установку Android CLI через Windows `install.cmd` без прав администратора. Выполни именно через `cmd.exe`, не через PowerShell download pipeline:

```powershell
cmd.exe /d /c "curl.exe -fsSL https://dl.google.com/android/cli/latest/windows_x86_64/install.cmd -o %TEMP%\android-cli-install.cmd && call %TEMP%\android-cli-install.cmd"
if ($LASTEXITCODE -ne 0) { throw 'Official Android CLI install.cmd failed.' }
```

Это допустимо даже при наличии записи WinGet: цель — получить реальный установленный `android.exe` и рабочий пользовательский PATH. Не удаляй существующий пакет WinGet без необходимости.

3. Найди фактический `android.exe`, не гадая путь
Сначала попробуй новый системный `cmd.exe`:
```powershell
$androidExe = (& cmd.exe /d /c "where android.exe" 2>$null | Select-Object -First 1)
```

Если не найден, проверь WinGet links/packages и пользовательские каталоги:
```powershell
$candidates = @()
$roots = @(
    (Join-Path $env:LOCALAPPDATA 'Microsoft\WinGet'),
    (Join-Path $env:LOCALAPPDATA 'Android'),
    (Join-Path $env:LOCALAPPDATA 'Google'),
    $env:USERPROFILE
) | Where-Object { $_ -and (Test-Path $_) }
foreach ($root in $roots) {
    $candidates += Get-ChildItem $root -Recurse -Filter android.exe -File -ErrorAction SilentlyContinue | Select-Object -ExpandProperty FullName
}
$androidExe = $candidates | Select-Object -First 1
```

Если `android.exe` всё ещё не найден — остановись и сообщи это как инфраструктурную ошибку. Не переходи к commit/push.

Проверь найденный бинарник:
```powershell
& $androidExe --help
if ($LASTEXITCODE -ne 0) { throw 'android.exe exists but does not run.' }
```
