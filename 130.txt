Problem
Internal CRM pages such as /reconciliation and /prices are lazy-loaded.
If loading the destination chunk is interrupted by Cloudflare verification, Vite emits vite:preloadError.
Current code reloads the current page before the Vue Router navigation has completed, so after verification/reload the user can land back on the previous route (often /) instead of the page they clicked.

Goal
Remember the intended internal route before lazy component loading starts and restore that exact route after the one-time stale-chunk reload.
Preserve fullPath, including query parameters and hash.

Exact scope
Only:
- src/main.ts

Implementation
- Store to.fullPath in sessionStorage from a global router.beforeEach hook.
- Do not overwrite the saved destination during stale-chunk recovery.
- Clear the saved destination only after a successful navigation; keep it on failed navigation.
- Keep the existing one-reload guard for vite:preloadError.
- After router.isReady(), if a stale-chunk reload happened and the saved destination differs from the current route, router.replace() the saved destination.
- Do not change Cloudflare, route definitions, Supabase auth, page-specific auth redirects, or lazy-loading strategy.
