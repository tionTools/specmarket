Применение
1. В C:\Users\Вадим\Documents\CRM моя\specmarket выполнить git fetch origin main chatgpt-patches.
2. Работать от актуального origin/main в отдельном чистом worktree.
3. Получить patch без изменения байтов:
   cmd /c "git show origin/chatgpt-patches:70.patch > 70.apply.patch"
4. Проверить SHA-256:
   (Get-FileHash -Algorithm SHA256 70.apply.patch).Hash.ToLower()
   Ожидаемый SHA-256: d052e1d305218cf787ecf5d593d65571191bf0ae0e0dfe464c5f23e83a7be89c
5. Выполнить:
   git apply --check 70.apply.patch
   git apply 70.apply.patch
   Remove-Item 70.apply.patch
6. Проверить, что изменён ровно один файл:
   .github/workflows/android-apk.yml
7. Выполнить git diff --check.
8. Статически проверить workflow:
   - permissions.contents = write;
   - существующая сборка, signature verification и upload-artifact сохранены;
   - шаг Publish stable latest APK выполняется только после успешной сборки/подписи;
   - tag = android-latest;
   - имя asset = app-release.apk;
   - существующий release обновляется с --clobber, отсутствующий создаётся;
   - versionName читается из android/app/build.gradle.kts;
   - заголовок и notes обновляются после каждой успешной сборки.
9. Commit только .github/workflows/android-apk.yml.
   Commit message: Publish stable latest Android APK
10. Перед push снова git fetch origin main. Если main изменился и git apply/check больше не соответствует актуальному workflow — остановиться и сообщить.
11. Push HEAD:main без force.
12. Дождаться success workflow Android APK, который должен запуститься из-за изменения самого android-apk.yml.
13. Проверить:
   - artifact orders-android-release создан;
   - release android-latest существует;
   - на странице https://github.com/tionTools/specmarket/releases/tag/android-latest видны актуальная версия и время успешной сборки;
   - asset app-release.apk существует и скачивается.
14. Сообщить commit SHA и GitHub Actions run ID.
