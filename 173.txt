АДРЕСНОЕ ИСПРАВЛЕНИЕ после второго STOP Codex (v3)
Ранее readback добавлял ВСЕ ordersWithoutTtn, включая непройденные пачки и запросы с ошибкой. Теперь ID для readback собираются ТОЛЬКО из успешно завершившихся targeted sync (data.ok === true и нет error): remoteId соответствующего заказа + changedOrderIds этого успешного ответа. Неудачные, отменённые и не запущенные запросы туда не входят.
Дополнительно readback вызывается с preserveMissing=true: отсутствие строки в ответе PostgREST НЕ удаляет заказ из orders/session cache; такой неполный readback возвращает false и выводит сообщение об ошибке, не объявляя список полным. У остальных вызовов refreshRemoteOrders поведение удаления отсутствующих записей неизменно (по умолчанию preserveMissing=false).
Обязательный регрессионный тест: создать 7–9 заказов без ТТН, смоделировать первую пачку из 4 (два ok, одна ошибка, один timeout), затем отсечку 30 секунд до второй пачки. Проверить exact ID set переданный refreshRemoteOrders: два подтверждённых remoteId и только их changedOrderIds; никаких ID 3/4/5/... . Смоделировать PostgREST, не вернувший одну из успешно проверенных строк: заказ должен остаться в orders и session cache, функция должна вернуть false. Проверить сохранение прежней семантики удаления отсутствующих строк для других вызовов refreshRemoteOrders без preserveMissing. Проверить ноль успешных ответов: readback не вызывается.
