What changed after review:
1. UserAuthenticationJWT retry is centralized in getValidNovaPayJwt and is exactly one retry.
2. Retryable auth failures are:
   - NovaPayTransportError (fetch failure, HTTP non-2xx, response body read failure)
   - NOVAPAY_SOAP_PARSE_ERROR
   - NOVAPAY_SOAP_RESULT_MISSING
   Logical NOVAPAY_API_ERROR is NOT retried.
3. response.text() is separated from XML parsing in both Edge Functions. A body-read failure is now a NovaPayTransportError.
4. A successful rotation response is persisted as one state payload; save_novapay_auth_state is retried once with the identical payload and authentication is not repeated.
5. Patch 96 behavior is reflected in tests: if stored jwt_expires_at is empty but JWT exp is valid, the shared JWT is reused.
6. Regression tests cover:
   - first transport failure -> second auth succeeds;
   - two transport failures -> second error is propagated, exactly two auth attempts;
   - unreadable/invalid XML auth response -> one retry;
   - logical NOVAPAY_API_ERROR -> no retry;
   - transient Vault save failure -> same payload save retried without re-authentication;
   - permanent Vault save failure -> stop after two save attempts;
   - invalid rotated JWT expiry -> never persisted.
7. Rotation logs contain stage names only; no refresh token, JWT, certificate, login, or credential values.
8. UI displays NovaPay API status/title already returned in Edge Function error details.
