Auth rotation behavior:
1. UserAuthenticationJWT is attempted at most twice.
2. Exactly one retry is allowed only when the first auth attempt has an unavailable/untrustworthy response:
   - NovaPayTransportError;
   - NOVAPAY_SOAP_PARSE_ERROR;
   - NOVAPAY_SOAP_RESULT_MISSING.
3. Recognized NOVAPAY_API_ERROR is not retried.
4. SOAP_TIMEOUT_MS now remains active through response.text(), not only until response headers arrive. A stalled/aborted body read therefore becomes a transport failure while the 20-second timeout is still active.
5. A successful rotation response is validated, then the complete refresh_token + public_certificate + JWT + expiry state is saved.
6. save_novapay_auth_state is attempted at most twice with the same payload. The save retry never invokes UserAuthenticationJWT again.
7. Rotation logs contain stage names only; no tokens, certificates, login, or credential values.
8. UI displays NovaPay API status/title details already returned by Edge Functions.

Regression tests:
- valid JWT reused;
- Patch 96 fallback: valid JWT exp is used when stored jwt_expires_at is empty;
- auth success and shared-state save;
- permanent save failure stops after two save attempts;
- transient save failure retries same state without re-authentication;
- first transport failure -> second auth succeeds;
- two transport failures -> stop after exactly two auth attempts;
- NOVAPAY_SOAP_PARSE_ERROR -> one auth retry;
- NOVAPAY_SOAP_RESULT_MISSING -> one auth retry;
- NOVAPAY_API_ERROR -> no auth retry;
- invalid rotated JWT expiry -> never persisted.

Known boundary:
- HTTP non-2xx is still classified as transport before SOAP-body interpretation, so a NovaPay logical error delivered only via HTTP 4xx/5xx could receive one retry. Recognized NOVAPAY_API_ERROR in a normal parsed result is not retried.
- No finite retry scheme can make credential loss mathematically impossible if NovaPay rotates successfully and the Vault remains unavailable for both save attempts. This patch reduces the identified transient-loss windows; it does not claim absolute durability across a sustained Supabase outage.
