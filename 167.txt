WHY
UserAuthenticationJWT rotates single-use credentials. If NovaPay is down when a JWT is expired, the current code immediately arms a persistent uncertainty guard and POSTs credentials. A timeout can require manual replacement of a fresh pair. We can skip known-offline periods BEFORE that sensitive POST.

DESIGN (ALREADY IN THE PATCH; DO NOT REDESIGN)
1. getValidNovaPayJwt checks the cached JWT as before. If still valid, do not issue GET preflight.
2. Only before an actual JWT rotation, while holding the existing owner lock and BEFORE begin_novapay_auth_rotation, invoke optional preflight callback.
3. Both novapay-data and novapay-balance supply checkNovaPayPreflight.
4. New shared check performs a credential-free GET to
   https://business.novapay.ua/Services/ClientAPIService.svc?wsdl
   with cache:no-store, redirect:error and an 8-second AbortController timeout.
   It accepts HTTP 2xx XML only. It does not read/log the response body, SOAP payload, or secrets.
5. If WSDL unavailable (timeout, network error, HTTP error, HTML/login response): fail with NOVAPAY_PREFLIGHT_UNAVAILABLE (HTTP 503), a safe reason code, NO call to begin_novapay_auth_rotation, NO UserAuthenticationJWT. Cron will retry at its existing cadence (usually 15 minutes).
6. If WSDL appears available, proceed through the existing atomic begin → one-shot POST → atomic save. Preserve all existing guards and failure handling unchanged.
7. WSDL GET is only a preliminary server availability signal; it is NOT proof the authorization backend is healthy or that the next POST cannot fail. A lost auth reply may STILL require manual credentials.
