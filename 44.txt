3. Prom: canonical family key только из Product API `variation_group_id`.
4. Хранить persistent variant-key -> family-key mapping, чтобы повторно не дергать Product API для уже известных Prom-вариантов.
5. Старые variant links не удалять и не переписывать. Если подтвержденный family имеет один и тот же `price_item_id`, безопасно создать canonical link.
6. Если внутри family обнаружены разные `price_item_id`, canonical family link не использовать и ничего автоматически не склеивать.
7. Ненулевые `cost`/`cost_usd`, `cost_manual` и существующие финансы старых заказов не затирать.
8. После успешного family resolution новые/обновленные `crm_order_items.marketplace_product_key` должны хранить canonical key.
