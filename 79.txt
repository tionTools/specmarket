Patch 79 — фактическое время события перевозчика

База main: 70f5dde060e4b36489365761216dbafead9fcaba

Причина: Patch 78 выводит delivery.trackingStatusChangedAt — момент, когда CRM заметила новый статус. Нужно выводить delivery.trackingEventAt — фактическое время события перевозчика.

Проверено по текущему backend: Nova Poshta, Укрпочта, Meest и Rozetka Delivery уже сохраняют trackingEventAt. Supabase менять не нужно.

Scope:
- src/pages/HomeView.vue
- src/features/orders/delivery-tracking.ts
- src/features/orders/types.ts

Что должно получиться:
- UI использует trackingEventAt, не trackingStatusChangedAt.
- Нет неточного fallback на trackingStatusChangedAt, trackingDataChangedAt или trackingLastCheckedAt.
- Timestamp показывается только при наличии trackingStatus и trackingEventAt.
- Формат HH:MM DD.MM.YYYY.
- DD-MM-YYYY, DD.MM.YYYY и YYYY-MM-DD без timezone сохраняют исходное локальное carrier-время.
- ISO с Z/offset переводится в Europe/Kyiv.
- Невалидная дата не показывается.
- Intl.DateTimeFormat создаётся один раз в feature-модуле.
- В template formatter вызывается один раз; v-if formatter не вызывает.
- Центрирование, absolute layout и line-clamp-2 из Patch 78 сохраняются.

Проверенные примеры formatter:
14-09-2026 12:11:00 -> 12:11 14.09.2026
14.09.2026 18:52:03 -> 18:52 14.09.2026
2026-09-14 12:11:00 -> 12:11 14.09.2026
2026-09-14T15:52:00Z -> 18:52 14.09.2026
2026-09-14T18:52:00+03:00 -> 18:52 14.09.2026
invalid -> пусто
