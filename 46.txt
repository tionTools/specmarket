Patch 46 — синхронная перепривязка canonical family и legacy price links

База: актуальный main = 4af3f25fa6b4958444facdffb99101ee4967e465 (`Allow canonical price relinking keys`).

Причина:
Patch 44 ввёл canonical family keys (`model:*` для Epicentr и `variation_group:*` для Prom) и сохранил старые variant-level links. Patch 45 разрешил открывать canonical key через кнопку «перепривязать». Но текущий `PricesView.vue` при перепривязке меняет только строку canonical key. Старые `product:*` / `offer:*` / `sku:*` / `external:*` links этой же семьи могут остаться на старом `price_item_id`. Следующая синхронизация тогда видит разные `price_item_id` внутри одной семьи и правильно объявляет conflict, из-за чего canonical family перестаёт использоваться.

Цель Patch 46:
1. Явная перепривязка товара на новую строку прайса должна переводить на тот же `price_item_id` canonical family link и ВСЕ уже существующие legacy price-link строки этой подтверждённой семьи.
2. Новые legacy price-link строки для вариантов, у которых их раньше не было, НЕ создавать.
3. Сохранить у старых legacy rows их собственные `product_title` и `size`; менять только `price_item_id` и `updated_at`.
4. Если пользователь открыл перепривязку из старого legacy key, но в `crm_marketplace_product_families` уже есть variant -> family mapping, операция должна автоматически работать через canonical family key.
5. Текущая позиция заказа после такой перепривязки должна хранить canonical key.
6. Kasta и legacy key без известного family mapping должны работать как раньше.
7. Не менять правило себестоимости текущего заказа: ненулевая или ручная `cost/cost_usd` не перезаписывается; новая стоимость автозаполняется только если обе стоимости нулевые и `cost_manual=false`.

Patch меняет только:
- `src/pages/PricesView.vue`
