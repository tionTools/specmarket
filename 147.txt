Problem:
Prom exposes buyer/client data and delivery/recipient data as separate concepts, but CRM currently cross-falls back between those phone fields. That can show/save recipient phone as buyer phone and vice versa. Production example: order prom:429674532 has buyer Пістоль Ірина / +380631230482 and recipient Батраков Петро / +380503316710, while CRM showed recipient phone in buyer block.

Behavior:
1. Buyer phone priority on targeted Prom sync:
   - Prom client card /clients/{client_id}
   - order.client_phone
   - order.phone only when it is not the explicitly detected recipient phone
   - previous CRM buyer phone only when it is not the explicitly detected recipient phone
2. Recipient phone comes ONLY from explicit recipient/receiver fields found by deliveryRecipientPhone(). No fallback to order.phone or order.client_phone.
3. Phone comparison normalizes formatting to digits so +38/spacing do not defeat the protection.
4. Frontend buyer block displays only order.phone. It never falls back to delivery.recipientPhone.
5. Cached/local order normalization no longer manufactures recipientPhone from buyer phone.
6. No DB migration, no RLS/grant changes, no unrelated fields touched.
