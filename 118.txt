Context
The previous NovaPay auth/circuit-breaker task is complete and already in production. Do NOT reopen or redesign auth in this task.
Natural production refresh after the JWT lifetime also passed.
Cron remains disabled.

Goal
Prevent overlapping full novapay-data refreshes, especially:
- cron + manual refresh;
- cron + cron;
- manual + manual.

The auth rotation lock is NOT a full-sync lock and must not be repurposed.

Patch behavior
1. Adds a dedicated public.novapay_full_sync_lock singleton and service-role-only RPCs:
   - acquire_novapay_full_sync_lock
   - renew_novapay_full_sync_lock
   - release_novapay_full_sync_lock
2. novapay-data acquires the full-sync lock before auth/API work and re-reads the cache after acquisition.
3. Lease is 600 seconds.
4. Before payment-event/cache writes, ownership is renewed. If ownership was lost or expired, the invocation stops with NOVAPAY_SYNC_LOCK_LOST before the stale cache write.
5. A scheduled request that finds another full sync running returns a successful skipped response:
   refreshed=false, skipped=sync_busy.
6. A manual refresh that finds another full sync running returns NOVAPAY_SYNC_BUSY (409).
7. Release is owner-checked and runs in finally. A stale owner cannot release a newer owner's lock.
8. Cron is NOT enabled by this patch.
