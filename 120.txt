Context
Patch 119 is being prepared separately for Prom order-status/completion UI and must not be mixed into this task.
Current NovaPay cron job 21 is active and pg_cron itself succeeds at :00/:15/:30/:45.
Observed scheduled HTTP response at 2026-09-19 13:00 UTC:
- HTTP 401
- code: UNAUTHORIZED_INVALID_JWT_FORMAT
- message: Invalid JWT
bank_account_cache for novapay remained at 2026-09-19 12:44:23.146+00.

Root cause
invoke_crm_novapay_sync() sends the Vault value crm_sync_cron_secret as:
Authorization: Bearer <cron-secret>

novapay-data intentionally accepts this secret inside the function and distinguishes it from a normal user JWT. However Supabase Edge gateway currently has JWT verification enabled for novapay-data, so the gateway rejects the opaque cron secret as an invalid JWT before novapay-data code runs.

Goal
Disable only the gateway JWT parser for novapay-data so the scheduled secret reaches the function. Do NOT weaken application-level authorization:
- scheduled requests are still accepted only when Authorization exactly equals Bearer <crm_sync_cron_secret>;
- all other requests still call auth.getUser() and reject unauthenticated/guest users.

Exact scope
Only:
- supabase/config.toml

Required change
Add:
[functions.novapay-data]
verify_jwt = false

Do NOT change:
- novapay-data source code;
- NovaPay auth/rotation/circuit breaker;
- full-sync lock;
- cron SQL or schedule;
- Vault secrets;
- Prom/Patch 119 files;
- any other Edge Function configuration;
- AGENTS.md or unrelated files.
