Context
Patch 125 is deployed and its running-balance math works for historical 18.09, but both 19.09 receipts became balance=null during the production smoke.

Observed:
- 18.09.2026 19:55:54 +1248.72 -> 7248.21 (correct)
- 19.09.2026 13:56:25 +125.37 -> null
- 19.09.2026 19:47:04 +626.85 -> null
- overall current account balance -> 8000.43
- refresh itself returned HTTP 200 with no auth/circuit-breaker error

Relevant current code
Patch 125 parses GetAccountExtract into:
  { opening: InCome, closing: OutCome }

For the current day it already overrides closing with fresh GetAccountRest.available_balance:
  closing: available

But if GetAccountExtract does not provide a usable current-day opening value, current code leaves:
  opening: null

assignRunningBalances intentionally refuses to calculate a day without both opening and closing, therefore all current-day receipt balances become null.

Patch 126 is intentionally tiny:
- keep the current-day opening returned by GetAccountExtract when present;
- only when today's opening is missing, use the previous calendar day's closing balance from the same GetAccountExtract result;
- keep today's closing = fresh available_balance;
- change nothing else.

Expected 19.09:
previous day 18.09 close = 7248.21
therefore current-day opening = 7248.21
13:56:25 +125.37 = 7373.58
19:47:04 +626.85 = 8000.43

Exact code change
Before:
  const todayBalances = dailyBalances.get(dateTo) ?? { opening: null, closing: null }
  dailyBalances.set(dateTo, {
    ...todayBalances,
    closing: available,
  })

After:
  const previousDate = formatNovaDate(new Date(now.getTime() - 24 * 60 * 60 * 1000))
  const previousClosing = dailyBalances.get(previousDate)?.closing ?? null
  const todayBalances = dailyBalances.get(dateTo) ?? { opening: null, closing: null }
  dailyBalances.set(dateTo, {
    ...todayBalances,
    opening: todayBalances.opening ?? previousClosing,
    closing: available,
  })
