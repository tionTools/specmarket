Goal:
- In custom date ranges, an impossible day for the selected month must clamp to that month's last valid day instead of rolling into the next month.
- Example: 31.09.2026 -> 30.09.2026.
- Same rule for February, April, June and November, including leap years.
- The corrected value must also be written back to the visible date field.
- Valid dates must remain unchanged.
- Apply the same normalization to both custom ranges already present in HomeView.vue: platform summary and order-list range.
- Do not alter day/week/decade/month/last30 semantics, comparison logic, filtering rules, or any other UI.

Scope:
- ONLY src/pages/HomeView.vue
- No database, Supabase function, migration, backend, route, auth, or unrelated formatting changes.

Implementation in the published patch:
- Adds normalizeInputDate(value).
- parseInputDate() uses the normalized value, preventing JS Date rollover.
- Watches platformSummaryFrom/platformSummaryTo/orderListFrom/orderListTo and writes a clamped date back when needed.
- Existing shiftDateByMonths() behavior stays unchanged.
