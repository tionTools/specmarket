5. Создай один постоянный keystore ВНЕ репозитория
Используй каталог-сосед репозитория:
`C:\Users\Вадим\Documents\CRM моя\android-signing`

Если после неудачного запуска там существует пустой/некорректный `orders-release.jks`, удали только этот некорректный файл. Если существует валидный keystore, не перегенерируй его без проверки.

Создай новый ключ только если валидного keystore нет:

```powershell
$repoRoot = (Get-Location).Path
$signingDir = Join-Path (Split-Path -Parent $repoRoot) 'android-signing'
New-Item -ItemType Directory -Force -Path $signingDir | Out-Null
$keystore = Join-Path $signingDir 'orders-release.jks'
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$pass = [Convert]::ToBase64String($bytes)
$alias = 'orders'
& $keytool -genkeypair -v -keystore $keystore -alias $alias -keyalg RSA -keysize 4096 -validity 10000 -storepass $pass -keypass $pass -dname 'CN=Orders Android,O=SpecMarket,C=UA'
if ($LASTEXITCODE -ne 0 -or -not (Test-Path $keystore)) { throw 'keytool failed to create keystore' }
@("alias=$alias","password=$pass") | Set-Content -Encoding UTF8 (Join-Path $signingDir 'orders-release-credentials.txt')
```

Проверь keystore ДО записи Secrets:
```powershell
& $keytool -list -keystore $keystore -alias $alias -storepass $pass
if ($LASTEXITCODE -ne 0) { throw 'keystore verification failed' }
```

Keystore и `orders-release-credentials.txt` должны оставаться вне репозитория. Никогда не выводи пароль, base64 keystore или приватный ключ в отчёт/чат/Git.
