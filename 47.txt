Patch 47 — история курса USD с датой начала действия

База: актуальный main = 3c30a44e9a69e4803bf3135c160a1c2290d845f6 (`Keep family price relinks consistent`).

Цель:
Перевести CRM с одного глобального `crm_settings.usd_rate` на историю курсов USD. Пользователь при изменении курса обязан указывать дату, с которой новый курс действует. Для заказа курс определяется по календарной дате самого заказа в CRM/Europe-Kyiv, а не по дате синхронизации и не по UTC-дню исходного timestamp.

Ключевые правила:
1. Источник истины — `crm_currency_rates` с `(currency='USD', effective_from, rate)`.
2. Курс на дату = запись с максимальным `effective_from`, не превышающим нужную дату.
3. Будущую дату разрешать: новый курс не влияет на сегодняшние расчёты до наступления этой даты.
4. Старые ненулевые `crm_order_items.cost` / `cost_usd` НЕ пересчитывать автоматически.
5. Если позиция ещё с нулевой себестоимостью и привязана к долларовой цене, при автозаполнении использовать курс на дату заказа.
6. Prom / Epicentr / Kasta используют именно отображаемую CRM-дату заказа в Europe/Kyiv.
7. Для ручного заказа и ручного редактирования `С/С $` использовать курс на дату этого заказа.
8. При выборе строки из `/prices` для существующего заказа, если себестоимость ещё нулевая, долларовую строку пересчитать по дате заказа.
9. `/prices` показывает курс, действующий сегодня, и историю курсов. Ввод нового курса: значение + дата начала действия.
10. Повторный ввод той же даты — корректировка курса на эту дату (`upsert`).
11. `crm_settings.usd_rate` оставить только как совместимый cache: после сохранения истории записывать туда курс, действующий СЕГОДНЯ. Исторические расчёты его не читают.
12. Сверка: текущая — курс сегодня; начальный остаток — курс на `initialDate`; старые сверки хранят свой `usd_rate`; `supplier_rate` платежей не менять.
13. Patch 44–46 не ломать.
14. Никакого молчаливого hardcoded fallback 45.2 для новых исторических расчётов: если таблица курса недоступна/пуста, не подставлять фиктивный курс и не создавать новую гривневую себестоимость из USD.

Критические корректировки после трансформера:
A. Epicentr timezone:
- НЕ оставлять `usdRateForDate(usdRateSchedule, source.createdAt)`.
- Использовать ту же Europe/Kyiv календарную дату, которая записывается в `crm_orders.order_date`: `usdRateForDate(usdRateSchedule, formatOrderDate(source.createdAt))`.
- Проверить границу полуночи: timestamp, который в UTC ещё предыдущий день, но в Kyiv уже следующий, обязан получить курс следующего Kyiv-дня.

B. Frontend fallback/error:
- В `PricesView.vue`, `HomeView.vue`, `ReconciliationView.vue` исторический курс должен вычисляться с безопасным fallback `0`, не с hardcoded `45.2`.
- Migration должна seed-ить реальный прежний `crm_settings.usd_rate`; поэтому нормальная production-система после migration имеет базовый курс.
- `HomeView.loadRemoteOrders()` обязан проверять ошибку чтения `crm_currency_rates`. При ошибке не использовать фиктивный 45.2 для USD->UAH; показать существующим механизмом ошибку/не выполнять неверную конвертацию.
- После успешной загрузки `currencyRates` ручной draft с `costUsd > 0` должен быть пересчитан по его `orderDraft.date`, чтобы восстановление draft/selection не зависело от race между загрузкой курсов и восстановлением формы.

C. Local date defaults:
- В `ReconciliationView.vue` `initialDate` должен инициализироваться через `localDateKey()`, а не `new Date().toISOString().slice(0, 10)`, чтобы около полуночи Kyiv не получить вчерашнюю UTC-дату.
- Новый курс в PricesView уже должен по умолчанию получать локальную дату через `localDateKey()`.

Обязательная проверка реализации:

1. `_shared/price-cost.ts`
- `loadPlatformPriceCostSnapshots()` не читает `crm_settings.usd_rate`.
- USD snapshot хранит `costUsd`; UAH не конвертируется заранее.
- `resolvedOrderItemCost(previous, linked, usdRate)` конвертирует USD только при заполнении конкретного заказа.
- Ненулевая/ручная существующая себестоимость не меняется.
- При отсутствии валидного курса USD-cost не должен превращаться в `cost=0` как будто расчёт успешен; позиция должна оставаться пригодной для последующего автозаполнения после появления курса.
- `price_item_id` может сохраняться без перезаписи ненулевой исторической себестоимости, как до Patch 47.

2. Prom
- `loadUsdRateSchedule(admin)` один раз на запуск.
- Курс по `date` из `dateParts(...)` (Europe/Kyiv), затем этот rate передаётся в `resolvedOrderItemCost`.
- Family/canonical логика Patch 44–46 без изменений.

3. Epicentr
- `loadUsdRateSchedule(admin)` один раз.
- Курс строго по `formatOrderDate(source.createdAt)` (Europe/Kyiv), НЕ по сырому UTC timestamp.
- Передать его в `resolvedOrderItemCost`.

4. Kasta
- Курс по `dateParts(createdAt).date` (Europe/Kyiv).
- Product-key логика Kasta без изменений.

5. `PricesView.vue`
- Старого inline-редактирования одного курса нет.
- Есть текущий курс + дата действия, `Новый курс`, `Действует с`, сохранение и read-only история.
- Upsert `crm_currency_rates` по `(currency,effective_from)`.
- После сохранения `crm_settings.usd_rate` обновляется только значением, действующим сегодня; ошибку cache-write не превращать в потерю сохранённой history row.
- Будущий курс не меняет сегодняшнее значение.
- Каталог `$ -> ₴` использует сегодняшний effective rate.
- Manual selection с USD не фиксирует сегодняшний UAH заранее; HomeView пересчитывает по дате draft.
- Relink существующего нулевого заказа читает `crm_orders.order_date` и использует курс этой даты.
- Patch 46 canonical/legacy relink сохранить.

6. `HomeView.vue`
- Читает `crm_currency_rates`, не `crm_settings.usd_rate`.
- Нет silent hardcoded 45.2 при ошибке чтения истории.
- Ручное изменение `С/С $` существующего заказа использует `order.date`.
- Draft использует `orderDraft.date`.
- Изменение даты draft пересчитывает все draft-позиции с `costUsd > 0` только в UAH, сам USD не меняется.
- После загрузки rate schedule также выполнить такой же reprice текущего draft, чтобы исключить race при восстановлении формы.
- Восстановление выбора из `/prices`: при `costUsd > 0` UAH = USD × rate(draft.date); иначе обычный UAH.

7. `ReconciliationView.vue`
- Читает историю курса.
- Сегодняшний `usdRate` = effective rate на localDateKey().
- `initialDate` по локальной дате.
- `saveInitialBalance()` фиксирует rate(initialDate).
- `saveReconciliation()` фиксирует сегодняшний rate.
- Старые строки и supplier_rate не пересчитывать.

8. Migration
- `crm_currency_rates`: USD only, `effective_from date`, `rate > 0`, PK `(currency,effective_from)`, authenticated read, guest write запрещён.
- Seed прежнего `crm_settings.usd_rate` с `effective_from=2000-01-01`, если >0.
- Никакого backfill/recalc старых order items.
