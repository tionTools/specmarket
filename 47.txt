Patch 47 — история курса USD с датой начала действия

База: актуальный main = 3c30a44e9a69e4803bf3135c160a1c2290d845f6 (`Keep family price relinks consistent`).

Цель:
Перевести CRM с одного глобального `crm_settings.usd_rate` на историю курсов USD. Пользователь при изменении курса обязан указывать дату, с которой новый курс действует. Для любого заказа/операции курс определяется по дате самого заказа/операции, а не по дате синхронизации.

Ключевые правила:
1. Источник истины — `crm_currency_rates` с `(currency='USD', effective_from, rate)`.
2. Курс на дату = запись с максимальным `effective_from`, не превышающим нужную дату.
3. Будущую дату разрешать: новый курс не влияет на сегодняшние расчёты до наступления этой даты.
4. Старые ненулевые `crm_order_items.cost` / `cost_usd` НЕ пересчитывать автоматически. История прибыли не должна плавать.
5. Если позиция ещё с нулевой себестоимостью и привязана к долларовой цене, при автозаполнении использовать курс на дату заказа.
6. Для Prom / Epicentr / Kasta автоматическая себестоимость должна использовать дату заказа, даже если старый заказ синхронизируется значительно позже.
7. Для ручного заказа и ручного редактирования `С/С $` использовать курс на дату этого заказа.
8. При выборе строки из `/prices` для существующего заказа, если себестоимость ещё нулевая, долларовую строку пересчитать по дате заказа.
9. Раздел `/prices` показывает курс, действующий сегодня, и историю курсов. Ввод нового курса: значение + дата начала действия.
10. Если пользователь вводит ту же дату повторно — это корректировка курса на эту дату (`upsert`).
11. Текущий `crm_settings.usd_rate` оставить только как совместимый fallback/cache: при сохранении истории обновлять его значением, которое действует СЕГОДНЯ. Он больше не должен быть источником исторических расчётов.
12. Сверка:
   - текущая сверка использует курс, действующий сегодня;
   - начальный остаток использует курс на выбранную `initialDate`;
   - уже сохранённые сверки продолжают хранить собственный `usd_rate`;
   - `supplier_rate` в платежах поставщику НЕ менять.
13. Patch 44–46 (canonical family / relink) не ломать и не менять архитектурно.

Обязательная проверка реализации:

A. `supabase/functions/_shared/price-cost.ts`
- `loadPlatformPriceCostSnapshots()` больше НЕ читает `crm_settings.usd_rate`.
- Для долларовой строки snapshot хранит `costUsd`, а `cost` не конвертирует заранее по сегодняшнему курсу.
- `resolvedOrderItemCost(previous, linked, usdRate)` конвертирует USD только в момент заполнения конкретного заказа.
- Ненулевая или ручная существующая себестоимость остаётся неизменной.
- `price_item_id` может быть заполнен без перезаписи ненулевой исторической себестоимости, как и до Patch 47.

B. Prom
- Один раз загружается `loadUsdRateSchedule(admin)`.
- Для каждого заказа после определения `date` выбирается `orderUsdRate = usdRateForDate(schedule, date)`.
- Именно этот `orderUsdRate` передаётся в `resolvedOrderItemCost`.
- Никаких title/name heuristics для family не возвращать; Patch 44–46 оставить как есть.

C. Epicentr
- Аналогично: rate schedule загружается один раз.
- Курс выбирается по `source.createdAt` / фактической дате заказа.
- В `resolvedOrderItemCost` передаётся order-specific rate.

D. Kasta
- Аналогично: курс по `createdAt` заказа.
- Kasta product-key/family логика остаётся прежней; Patch 47 касается только валютного курса.

E. `src/pages/PricesView.vue`
- Старого прямого inline-редактирования одного `usd_rate` больше нет.
- Есть текущий курс + дата, с которой он действует.
- Есть поля `Новый курс` + `Действует с` (date) + сохранение.
- Есть read-only история курсов.
- Сохраняется `crm_currency_rates` через upsert `(currency,effective_from)`.
- После сохранения `crm_settings.usd_rate` обновляется только текущим на сегодняшний день курсом для совместимости.
- Будущий курс не меняет сегодняшнее значение.
- Каталог цен пересчитывает `$ -> ₴` по курсу, действующему сегодня.
- При выборе строки для ручного заказа долларовая сумма в UAH не фиксируется сегодняшним курсом заранее: HomeView должен пересчитать её по дате заказа.
- При relink существующего заказа с нулевой себестоимостью PricesView читает `crm_orders.order_date` и применяет курс этой даты.
- Логика Patch 46 синхронной canonical/legacy перепривязки должна остаться неизменной.

F. `src/pages/HomeView.vue`
- Загружает `crm_currency_rates`, а не `crm_settings.usd_rate`.
- `usdRate` для сегодняшнего интерфейса вычисляется из расписания.
- Ручное изменение `С/С $` существующего заказа использует `order.date`.
- Ручной draft использует `orderDraft.date`.
- Если дата ручного draft меняется, все позиции draft с `costUsd > 0` пересчитывают только гривневый `cost` по новому курсу даты; сам `costUsd` не меняется.
- Восстановление manual price selection из `/prices`: если `costUsd > 0`, UAH вычисляется по дате draft; если USD нет, берётся обычный `costUah`.
- Другие поля заказа не менять.

G. `src/pages/ReconciliationView.vue`
- Загружает историю курса.
- Текущий `usdRate` = курс на сегодня.
- `saveInitialBalance()` фиксирует курс на `initialDate`, а не текущий.
- `saveReconciliation()` фиксирует текущий сегодняшний курс в собственной строке `crm_reconciliations.usd_rate`.
- Исторические строки сверок и `supplier_rate` платежей не пересчитывать.

H. Migration
- Таблица `crm_currency_rates`:
  - `currency` только `USD`;
  - `effective_from date`;
  - `rate > 0`;
  - primary key `(currency,effective_from)`;
  - RLS: authenticated read; write запрещён guest@gmail.com.
- Seed: существующий `crm_settings.usd_rate` записать как базовый курс с `effective_from = 2000-01-01`, только если он положительный.
- Никакого массового пересчёта старых `crm_order_items`.
