Problem:
Supplier debt is calculated from current cost totals for orders that have a non-empty TTN. When a new order/TTN is saved, the database total changes immediately, but the BankBalancesCard keeps showing its old supplierDebt value until page reload. Accepted returns and order deletion already call refreshDebt() explicitly.

Fix:
- After save-crm-orders succeeds in persistOrdersNow(), refresh BankBalancesCard supplier debt.
- After refreshRemoteOrders() applies marketplace/realtime changes, refresh supplier debt.
- Existing behavior for accepted returns and order deletion remains unchanged.
- Do NOT change debt accounting rules: an order without TTN must still not enter current cost totals; a replacement TTN must not add cost twice; accepted returns reduce remaining cost.
- Frontend only: no schema, migration or Edge Function changes.
