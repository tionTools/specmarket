Root cause:
The order card already treats delivery.trackingReturnInProgress=true as an active return even after the carrier current checkpoint becomes ordinary movement such as in_transit. The Returns filter only checked isReturnLifecycleState(lifecycleState), so such a return could be omitted.

Fix:
When the Returns filter is active, include the order if either:
1. order.delivery.trackingReturnInProgress === true; or
2. the existing lifecycle state is a return lifecycle state.

Required accounting invariants preserved:
- trackingReturnInProgress does NOT change getOrderLifecycleState.
- trackingReturnInProgress does NOT change includeInUnpaidShipment.
- a physically shipped order returning to sender stays in the "В дороге" amount until the return is actually accepted.
- supplier debt/current cost is reduced only by crm_order_item_returns.returned_quantity, not by tracking state.
- partial accepted returns reduce only the confirmed quantity.
- full accepted return removes the remaining quantity/cost.
