Goal:
Add the first read-only NovaPay Business API backend integration for SpecMarket: authenticate with UserAuthenticationJWT, rotate the single-use refresh token/certificate pair safely, discover the enterprise and active UAH account, and return the current account balance through a Supabase Edge Function.

Scope — exactly 2 files:
- supabase/functions/novapay-balance/index.ts

What changes:
- Adds authenticated Edge Function novapay-balance.
- Reads NovaPay refresh token and public certificate from Vault using the existing service-role RPC.
- Calls NovaPay UserAuthenticationJWT.
- Immediately persists the newly returned refresh_token + public_certificate via existing rotate_novapay_credentials before proceeding.
- Adds a service-role-only database lease lock so parallel Edge Function workers cannot rotate the same NovaPay credential pair concurrently.
- Uses the resulting JWT for GetClientsList, GetAccountsList and GetAccountRest.
- Automatically uses the account only when exactly one active UAH account exists; otherwise returns a controlled selection-required error instead of guessing.
- Returns account id/IBAN/currency plus confirmed, available and projected balances.
- Does not add UI, Android code, payments, statements or write-payment functionality.

Security:
- No NovaPay credential is stored in frontend or Android.
- No refresh token, JWT or certificate is returned to the caller.
- No secret value is intentionally logged.
- Function follows the existing project auth pattern and rejects unauthenticated/guest users.
